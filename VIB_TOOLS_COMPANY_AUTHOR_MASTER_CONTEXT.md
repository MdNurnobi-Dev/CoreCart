## 12. Open-Source & Contribution Policy Context

### Public Project Principles

- Many Vib Tools projects expose source code publicly.
- Public repositories may include source, release history, issues, documentation, and contribution paths.
- Licensing is determined at the individual repository level.
- Never assume every project has the same license.
- Check the project’s `LICENSE`, `NOTICE`, `SECURITY.md`, `CONTRIBUTING.md`, README, and release documentation before making legal or technical claims.

### Contribution Workflow

Where contributions are accepted:

1. Read the target repository documentation.
2. Check existing issues/discussions.
3. Keep pull requests focused.
4. Explain the problem, fix, and testing clearly.
5. Respect the repository architecture, license, contribution rules, and security policy.

### Security Reports

Follow the target repository’s `SECURITY.md`.

When a repository directs private security/support questions to Vib Tools support, use:

- support@vib.tools

Do not publish sensitive security findings in public issues when the repository policy asks for private disclosure.
